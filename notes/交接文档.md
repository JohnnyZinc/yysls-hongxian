## 0.5 统一面板 schema（本次改造定稿，覆盖下文一切旧键名描述）

用户拍板："项目内部一律使用游戏全称，不用简称；输出即输入，不做第二层转换。" 本文 §3/§4 中出现的旧简称（全武增/首领增/奇术增/最小外功/会心伤害/直接会心率 等）一律按本节替换理解：

1. **panel.js 输出 = dps.js 输入**，同一个形状 `{ stats, 五维达标率, 主属性达标率, warnings }`，`toDpsPanel` 已删除。stats 键全称化：最小外功攻击/最大外功攻击/最小破竹攻击/…/最小无相攻击；全武学增伤/对首领单位增伤/全奇术增伤/对玩家单位增效；会心伤害加成/会意伤害加成；直接会心率/直接会意率（用户纠正过"直议会心率"是错字）。
2. **指定武学增伤按武器类型进 stats**（`双刀武学增伤`/`剑武学增伤`/…共10类，与对首领单位增伤同级、无条件出键含 0；零值过滤是 UI 的事）。`stats['武器增']` 占位标量已废除。
3. **技能定音为单一数值**（stats['技能定音']）：定音**名字的唯一来源 = 方案文件的 `防具定音` 字段**（展示与添加装备预填用，牵丝霖可留空）；**引擎只认数值**：computePanel 无条件把护甲定音词条数值计入 stats['技能定音']，不看名字、不警告（定音可随意重掷，数值才是事实）。`build.dingyin_affix`、prescription `idealArmorDingyin`、advisor 定音匹配提示**均已删除**（derivePrescription 恢复三参）；更早 `data/version/dingyin-map.json` 双写也已删除。破竹风"轻击定音"为死数据（真实可掷但无人用，掷出即重掷），已从数据包清除，对应 skills 事件的 dingyin_type 标记已删。
4. **最终生效三率**（panel.js 新增，不含技能级标记的基准值；技能级修正在 dps.js）：bo=min(1,精准率)，bp=min(0.8,会心率)+直接会心率，br=min(0.4,会意率)+直接会意率；最终生效会心率=bo×min(bp,1−br)（会意+会心>100% 时挤占），最终生效会意率=br，最终生效会心会意率=两者之和。公式出处：`知识库/燕云十六声的四种伤害与三率.md`。
5. **守卫**（用户拍板"多了不管，缺了得报错"）：dps.js 对面板必需键做齐全性校验，缺键抛错并列出缺什么；panel.js 对未识别的装备词条给警告；未知流派定音/不匹配定音给警告。
6. **奇术合并**：游戏已把单体/群体奇术增合并为全奇术增伤，六流派包 config.categories 已合并为单个"奇术"类（panel_key=全奇术增伤，继承原 panel_keys 与 includes_all_weapon——牵丝玉/牵丝霖的奇术增缓存 0.2677 非零，是 Excel 基准的一部分，勿删行）；skills.json 的 type 单体/群体奇术→奇术。
7. **测试基线**：黄金基准 `tools/test_golden.js`（面板/六流派逐事件/ΔDPS 四场景快照，`--update` 重新固化前必须人工审查差异）+ 原 Excel 对表测试并存。本次审查后固化的两处有意变更：面板 schema 键名；ΔDPS 基准中装备无定音时不再继承作者默认定音 0.3206（verdict/档位判定不变）。
8. **待办清账（收尾完成）**：两个提取器原先归档在 archive/（该目录已于 2026-11-03 删除，需要时用 git 历史找回；重用前须同步产出形状，见盘点 §3.4）；数据架构盘点.md / 评价系统设计.md 旧键名描述已清理；skills/effects 内部英文键 = 盘点议题F开放项（改 DPS 计算块时再评估）。

## 4. 游戏机制备忘（新会话必需，全部经 Excel 对照或实测验证）

### 4.0 术语：流派 / 轴 / 流（用户定义，全项目勿混淆）

- **流派** = 玩家选择的武学组合。例：鸣金虹=无名剑法+无名枪法；破竹鸳=天志垂象+千机索天；牵丝玉=九重春色+青山执笔；破竹风=泥犁三垢+粟子游尘；裂石钧=斩雪刀法+十方破阵（数据内标签暂为"裂石威"，显示名映射待确认）。
- **轴** = 流派之内不同的打法。例：裂石钧纯唐轴（主要靠唐横刀施展斩雪刀法打伤害）/ 裂石钧双切轴（主要靠陌刀施展十方破阵）；牵丝玉飞天轴（轻击蓄力飞天技为主）/ 走地轴（九重春色特殊技为主）。同一流派不同轴对装备的要求可能不同、也可能相同，具体情况具体分析。
- **流** = 装备层面如何配置词条（大外流/小外流等）。分野根源：游戏机制规定最小外功攻击超过最大外功攻击之后，伤害固定取最小外功攻击值——于是出现追求伤害稳定的小外流与追求上限更高的大外流。例：裂石钧纯唐轴大外流、裂石钧纯唐轴小外流，两者对装备词条要求不同。
- 完整评价语境 = **流派 × 轴 × 流**。DPS 三件套（build/skills/effects）挂在"流派×轴"；评价层配置（配额表/达标线/优先级分层）允许逐层继承（流派级默认→轴级覆盖→流级覆盖）。详见 `评价系统设计.md` §1。

### 4.1 面板计算（panel.js）
- **三层来源**：固定层（等级+突破+天赋+蹊跷+叠音+装备基础数值，全玩家一致）/ 可选层（弓玦+装备套装+心法×4+武库+武学天赋）/ 装备词条（8部位×初始1+调律4+定音1）
- **转换规则**（主表 W 列公式）：
  - 判定抗性 1.8：精准率 = 65%基线 + (raw−65%)/2.8；会心率/会意率 = raw/2.8
  - 增益抗性 0.32：**装备词条的外功穿透** ÷1.32（可选层不除）；技能定音/全武增/首领增/武器增/奇术增 **全额** ÷1.32
  - 五维贡献：最小外功 += 劲×0.22+敏×0.9；最大外功 += 劲×1.36+势×0.9；会心率 += 敏×0.076%；会意率 += 势×0.038%（用最终五维值）
  - 武学天赋双达标率：会心/会意/外功天赋 ×MIN(五维/492,1)；主属性攻击天赋(328/656)**不缩放**；主属性穿透/加成天赋 ×MIN(最终主属性/要求值,1)——**词条→主属性→天赋加成存在二级传导**
  - 其余属性纯求和
- **词条名↔区间表名存在系统性别名**（全奇术增伤→奇术增伤、对首领单位增伤→首领单位增伤、对玩家单位增效、指定武学增伤→武器增伤、护甲定音55条→技能定音），统一由 panel.js 的 `lookupRange` 处理，有测试覆盖
- 转律池**不含**任何神力词条与精准率——神力只能来自初始/调律，转掉就回不来（将来推荐转律功能的重要约束）

### 4.2 DPS 计算（dps.js）
- **逐事件模拟**：展开式时间轴（每事件=技能+次数+人工标注的生效增益列表），非状态机
- **四态期望加权**：会心(均值攻×生效会心伤害)×BT + 会意(大攻×生效会意伤害)×BR + 普攻×BU + 擦伤(小攻)×BV；强制会心/会意/精准为技能级标记；debug 已透出 生效精准/生效会心/生效会意/会心占比/普攻占比/擦伤占比
- **三率→四态生效概率链**（知识库/燕云十六声的四种伤害与三率.md，已与引擎逐行对上）：白字三率（面板累加）→ 黄字三率（panel.js：精准=65%+(raw−65%)/2.8、会心/会意=raw/2.8，**无 cap**）→ 最终会意/会心率（dps.js：min(0.4/0.8, 黄字+技能级加成)+直接会意/直接会心率，直接项不受 cap）→ 四态生效概率（逐技能）：生效会心 **BT=min(黄字精准×(1−最终会意), 黄字精准×最终会心)**——min 即"会意+会心>100% 时会心被挤占"；生效擦伤 BV=(1−黄字精准)×(1−最终会意)；生效普伤 BU=1−BT−BR−BV；四者之和恒为 1 → 期望 L=M×BT+N×BR+O×BU+P×BV
- **口径辨析**：面板黄字会心率 ≠ 最终会心率（BP=黄字cap+直接项）≠ 最终生效会心概率（BT=会心占比，含精准门与挤占）。破竹风达标线挂**黄字会心率**；裂石钧双切轴"孤忠不辞 75% 必会心"挂的是 **BT（逐技能，重击蓄力技行）**——达标线系统必须支持技能级口径
- **乘区链**：即时攻击(扣防御)→穿透分段(>0÷200,≤0÷100)→伤害加成→通用增伤→会意伤害倍率→次数→定音→特殊/特定增伤
- **主属性结算**：主属性的属性倍率+固伤×1.5，非主属性用外功倍率；无相攻击只加给主属性
- **会意转化**（破竹鸢3.0 新机制，技能级"会意转化"标记）：会意率生效值并入会心率（至多 12%），生效会意扣减同值（地板 0）；引擎在 BP/BR 内实现
- **强制精准**：无擦伤（BV=0）——只影响擦伤占比，不影响生效会意（裂石威/破竹樽的强制精准技能会意正常，勿过度泛化）
- **奇术类别别名**：单体奇术/群体奇术类技能同用"奇术"类别的全奇术增伤乘区（奇术单类合并后的别名注册）
- **覆盖公式 (1+XY) 的增伤列按表头名解析**（结算增伤→final_dmg、特定增伤→spec_bonus），不再写死 BY——各流派/版本的增伤列位不同
- **无相=动态本属（评价层抽象的依据）**：无相 min/max 只加给 mainLabel（dps.js attrs 映射 `isMain ? wxMin/wxMax : 0`）——对**任何**流派，无相词条都是本属；具名属性攻击词条（鸣金/裂石/牵丝/破竹）仅对同属流派是本属，对其他流派是外属。评价层据此把攻击词条抽象为：本属·无相 / 本属·具名 / 外属
- **最小>最大攻击规则**：Excel 用 MAX() 收敛到最小值，引擎已忠实翻译（外功与四种具名属性攻击；无相不适用）——小外流"伤害固定取小外"是引擎现成行为，无需改动
- **覆盖事件**：破竹风"结算"×30%、破竹尘"结算"×12%、破竹樽"醉杀"×20%（=SUM(引用行)×系数×(1+结算增伤)，可能有前向引用）→ 引擎两遍计算（先标准行后覆盖行）
- **套装攻击乘数**：从各流派 D10 公式解析（倾觞×1.05 等），存 build.set_attack_multiplier
- **毕业率** = DPS / 毕业基准；基准由当前方案配额物化生成（engine/graduate.js，按流各自基准、自检配额恰好+逐件全天），无方案回退 build.graduate_dps（Excel I16，同时作为对照并在页头显示偏差）。**物化数值口径=承音值**（用户定稿 2026-10-22 由满值改回）：**毕业 = 玩家现实能达到的状态**，承音是重掷收敛后的实际可达上限（≈max×94%），满值（区间最大值）只是理想 roll、实战不存在，只作理论参考；物化件对应标 `承音:true`。
  - **改口径的实证**（用户提出、已被数据验证）：方案配额是按承音值设计的。满值口径下 22 个方案里 **17 个三率超游戏上限**（会心普遍 82~83% > 80%）；
    改承音值后 **22/22 全部不再溢出**（鸣金虹会意 39.8%、鸣金影 40.0%、裂石钧会心 79.3%），说明配额作者（如鸣金虹 7势+6会意）本就是按承音值凑达标线；
    这也解释了"满值下 8势5会意 反而更优"的现象——那是满值语境下的另一套最优解，不是方案的意图。

## 5. 关键设计决策（含"为什么不"，勿轻易推翻）

1. **1 引擎 + N 流派数据**（否决了"11个独立计算器"）：游戏更新多为跨流派共性改动；流派差异只体现在数据。若某流派公式结构真的不同，用 build 级 `custom_rules` 扩展点，不复制引擎。
2. **展开式时间轴，不做 buff 状态机**：PVE 里流派的心法/套装/配队固定，唯一变量是装备词条→面板。Excel 作者人工标注增益列表，直接沿用。配置切换（如第四心法换易水歌）不做——固定参照系下 ΔDPS 排序基本不受影响（用户拍板）。
3. **DPS 内部化**：玩家只见"更好/更差/等价+毕业率+提醒"，不见绝对 DPS。等价死区阈值 |Δ%|≤0.3%~0.5%（可配），等价时用毕业度做次级排序；组合优化输出"等价类"而非单点最优。
4. **毕业模板与 DPS 分工**：模板给方向（毕业度评分），DPS 做最终裁决。冲突时以 DPS 为准。
5. **牵丝霖是奶妈**：其 DPS 全靠奇术（时间轴 90% 是 N/a 占位），装备评价不走 DPS——用模板对照（`evaluation: "template"` 路由，P3 做），先跳过。
6. **数据全 JSON 分层**：版本数据包按赛季组织，用户自己维护（每个赛季=突破+1×2、装备等阶+1×1）；公式逻辑留在引擎。
7. **套用 Excel 的口径而非"更合理"的口径**：例如"会心伤害 0.544 超出 0.5 的部分"已由用户真实装备复现，模型自洽。
8. **三系统共同评价、地位相当**：匹配度（留什么）/ 监测（找什么）/ ΔDPS（穿什么）并列呈现，开发顺序 匹配度→监测→ΔDPS→整合（用户定）。DPS 仍是内部裁决依据之一，但不再是展示层唯一主角。
9. **配额只维护全局，部位级自动推导**：用户数据形态 = 每流派（×轴×流）需要多少条什么词条；部位级必备/自由集由推导器按词条池与重复规则计算（破竹风大外流已实证几乎整表唯一，见 `评价系统设计.md` §3）。
10. **毕业度=纯结构分档**：roll 数值不入档（承音收敛到 max×94%）；按"转律最优解"后的 (k,m) 评天地玄黄；定音不入档（可随意变音）。
11. **属性面板：攻击区间合并成一行**（用户定稿，勿回退成最小/最大两行）：`外功攻击 / {主属性}攻击 / 鸣金攻击 / 裂石攻击 / 牵丝攻击 / 破竹攻击 / 无相攻击` 均显示为 `最小~最大`；最小≥最大（反转）时改写成 `最小↑`（伤害固定取最小攻击，与监测"已反转"口径一致），**无相攻击例外：恒定按区间显示，即使最小>最大也不改写**（`无相攻击 250~79`）。0/0（无数据）不标反转。实现：`web/studio.js` 的 `atkRangeText()` / `atkPairRow()`；属性攻击元素清单派生自词条区间键（与 `engine/panel.js` attrAtkKeys 同源）。
12. **切换「流」会改变属性面板是正常行为**（不是 bug，勿"修"）：方案文件自带口径默认值（心法×4/武库/装备套装/**弓玦**），`switchFlow → applyPlanDefaults()` 会写进 `state.selections`，而这四项都是面板的可选层（`panel.js` 的 `optSource`），所以面板、DPS、毕业率都会跟着变。实证：裂石钧「双切轴大外流」弓玦=**惊弦**（会心率+8%）而其余三个裂石钧流=**饮羽**（精准率+7.2%），故切这两个流面板变（精准率 +2.57pp / 会心率 −2.86pp / 最终生效会心率 ±1.52pp，均除以判定抗性 2.8）；破竹风两流弓玦都是饮羽，故面板不变。**用户拍板：保持数据现状**（双切轴大外流敏只有 4 条、会心缺口大，惊弦疑似有意）。弓玦下拉显示名附俗称 `饮羽（精准弓）/惊弦（会心弓）/追影（会意弓）`，俗称由它提供的面板属性派生（`web/studio.js` 的 `gongjueLabel()`），option value 仍是原名，数据键不变。
13. **属性面板=定序平铺、无分组标题**（用户定稿，勿重排/勿加回分组）：顺序为 外功攻击 → 外功穿透 → 无相攻击 → 主属性攻击/穿透/加成 → 其他属性攻击（非零才出）→ 精准率/会心率/会意率/直接会心/直接会意 → 最终生效三率 → 会心伤害加成/会意伤害加成 → 指定武学增伤（按武器类型逐条，非零才出；双武器=两条）→ 全武学增伤 → 全奇术增伤 → 对首领单位增伤 → 对玩家单位增效 → 技能定音 → 体/劲/御/敏/势/气血最大值。**技能定音那行的标签用真实定音词条名**（优先已穿戴护甲的实际定音名，其次方案 `防具定音`），不显示"技能定音"/"指定技能增伤"字样。实现：`web/studio.js` 的 `statsHtml()` 按序 push；`dingyinLabel()`。

14. **监测·达标线也用配额同款统一行**（用户定稿）：`指标名　当前/阈值`（比率按 1 位小数，如 `最终生效会心率　74.0%/75.0%`），**全量列出（含达标行）**；配色只有两态——**不足=黄 `st-q-low` / 大于等于=绿 `st-q-ok`**（**超过阈值是好事，无"溢出"红态**，与配额的红=坏语义不同，勿混）。悬停 title = 该指标的口径声明（来自 PANEL_METRICS）+「差 X%」或「已达标（超出 X%）」。实现：`inspect.js` 的 `monitoringDigest` 新增 `达标行`（全量，`达标未达` 切片保留）；`fmtMetric(x, digits)` 已支持小数位。
15. **监测·配额三合一为统一行**（用户定稿，勿拆回缺口/溢出/未配额三个分组）：所有配额行（**含达标行**）统一渲染成 `词条名　　实装/需要`，只给右侧数值上色——**相等=绿 `st-q-ok` / 少于=黄 `st-q-low` / 多于=红 `st-q-over`**；未配额词条按"需要 0"并入同一张表（`词条名　N/0`），**整行红**（含名称）。悬停 title 提示"缺 N 条/多 N 条/配额已满足/未在方案配额中（白占槽位）"。实现：`engine/inspect.js` 的 `monitoringDigest` 新增 `配额行`（全量），`缺口/溢出` 两份切片保留给程序化消费（test_inspect 前瞻断言）；`web/studio.js` 的 `digestHtml()` + `studio.css` 的 `.st-qrow/.st-q-*`。定音永不入统计（独立池）。
16. **小外流启用度：只提示事实、不下结论**（用户定稿）：① **仅小外流方案**显示——判定靠方案数据字段 `小外流: true`（8 个 `*.xiaowai.json` 均已标注），**不再按"配额含最小外功攻击行"判定**（该旧口径把只配 1 条/4 条的「双切轴大外流」「纯奶大外流」也误判为小外流）；② 最小外功 **>** 最大外功（已达成，伤害固定取最小外功）→ **不显示任何文案**；③ 未达成 → 只显示一行醒目提示 `⚠ 当前最小外功攻击 X 小于最大外功攻击 Y`（`.st-xw-alert` 加粗+色条）。**不再输出"距反转差值/还差 N 条小外词条"**——成因可能是缺小外或敏，也可能是大外/劲/势多了，无法由差值反推。实现：`engine/monitor.js` 的 `enablement(panelStats, flow)`（已去掉 affixes 参数与折算逻辑）。
17. **方案配错的防线在构建期，不在用户界面**（用户定稿）：方案是**运维（站主）编写**的，不是玩家输入，所以配错应当在测试/构建期炸掉，而不是运行时在监测面板弹警告。`engine/monitor.js` 的 unknown 指标 warning 降级为**兜底保险**（正常流程不该走到，UI 不展示）。防线主体 = `tools/check_templates.js`（`npm run check:data`，已并入 `npm test` 链首，快速失败），校验：三层骨架（流派=目录名、分支/方案齐备、不得残留 name/buildId/小外流）、文件名=`<流派>[.<分支>].<方案>`、方案必须在 `version.方案类型` 枚举内、分支必须在 `_meta.json` 分支表内（有中文名）、配额行 any_of 词条能在版本包查到区间、**配额总数 = 8×5 = 40**、达标线指标必须在 `PANEL_METRICS` 白名单内且值 ∈ (0,1]、心法×4/武库/套装/弓玦 在版本包存在、定音名能查到区间、死区 ∈ (0,1)、**manifest ↔ template 三方对齐**（35/35）。已用注入错误做过负向验证（未知词条/未知指标/漏标小外流三类都能拦）。
18. **配额行名称压缩显示**（任选池显示不全的对策，用户定稿）：`最大裂石攻击/最小裂石攻击/最大无相攻击/最小无相攻击` 这类 4 选 1 的任选池，UI 合并成 `裂石攻击/无相攻击`（与属性面板"最小/最大合并"同口径）；**只有单边时保留原名**（小外流的「最小外功攻击 ×12」不得显示成「外功攻击」，否则与大外流混淆）。完整候选名移到行 title（悬停可见）。实现：`web/studio.js` 的 `quotaLabel()`（纯函数，已导出到 `__test`）；统计口径不变（仍按原始词条名计数）。
19. **thresholdNotes 字段已彻底删除**（用户定稿）：达标线口径由 `engine/monitor.js` 的 `PANEL_METRICS` 登记表权威承载（每行 rows 自带 `口径` 字段），方案里不再写口径注记——两处口径会打架。`evaluateThresholds` 不再返回 `notes`，`analyzeFlow` 的 `口径` 不再有 `达标线` 键。

      提取时必须用第 6 个 CLI 参数显式指定，否则 `panel_input` 会缺 `dingyin`。
    - **套装攻击乘数作用域** `build.set_attack_scope`（`"外功"` / `"全部"`，提取器按 D10 与
      D11:D14 各行是否都写了 `IF($G$2=套装,X,1)` 自动判定）：115 阶表外功+四属性各乘一次；
      **110 阶表只乘外功**（鸣金影·飞隼×1.1）。引擎 `dps.js` 按此决定属性攻击是否也乘——
      不区分会让鸣金影属性攻击虚高 10%、DPS 比源表多 1.83%。
22. **三率上限：面板按上限显示，溢出提醒归监测面板**（用户定稿 2026-10-22，勿回退）
    - 三率的**游戏机制上限**：精准率 100% / 会心率 80% / 会意率 40% —— 权威数值在
      `version.constants`（`精准率上限`/`黄字会心率上限`/`黄字会意率上限`），引擎登记表
      `monitor.js RATE_CAPS` 只存键位与缺省，UI 从同一张表取，禁止另写一份数字。
    - **属性面板**：超上限则**显示上限值**，不弹「⚠溢出」标记；真实面板值只在 hover
      title 里给出（`面板值 X，超出游戏上限 Y，按上限显示`）。
    - **监测面板**：单列一个「**三率溢出（游戏机制上限）**」分组，行格式 `指标名　当前/上限`
      （数值红），tip 给「超出 N%」；**只在溢出时出现**，未溢出不占版面。
    - **必须与「方案达标线」区分**：达标线 = 方案作者的期望值（达不到只是不够好）；
      上限 = 游戏硬性截断（超出部分完全浪费）。两者是两份独立切片
      （`analysis.达标线` vs `analysis.三率上限`），分组标题与脚注都要写明这层区别。

## 6.5 性能与缓存（2026-11-03 上线后定稿）

**问题**：GitHub Pages 固定返回 `Cache-Control: max-age=600` 且不能改响应头 → 隔 10 分钟再打开，
浏览器仍要为几十个资源逐个发条件请求；跨境链路下首屏实测 **DOMContentLoaded ≈ 8.5s**，
其中字体发了 90+ 个 woff2（2.76MB）、首屏图 ≈1MB。瓶颈是「请求数 × 跨境 RTT」，不是单纯字节。

**三项措施（已上线，代码在 `sw.js` / `assets/fonts/kai/` / `data/version/<赛季>/version.json`）**：

1. **Service Worker**（根目录 `sw.js`）
   - 导航 network-first（4s 超时回落缓存）；`assets/`、`web/`、`engine/` stale-while-revalidate；
     `data/` 与 `知识库/` network-first（1.5s 超时回落缓存）；非 GET/跨源/`cache:'no-store'` 放行。
   - `BASE = new URL(registration.scope).pathname`，因此自定义域名根与 `/<repo>/` 子路径都成立。
   - 三个缓存名 `yysls-{shell,asset,data}-<CACHE_VERSION>`；**改资源后 CACHE_VERSION +1**，
     activate 会清掉旧缓存。`tools/check_site.js` 第 7 项会验证 sw.js、注册脚本、SHELL 目标。
   - 本地二次打开实测：111 个请求里 110 个由 SW 命中，transfer ≈ 0KB。
2. **字体单文件子集**：71 分片（2.76MB）→ `assets/fonts/kai/gkai00mp.woff2`（357KB，1463 个用字，
   合并自 7645 字形）。`index.html` 加 `rel="preload" as="font"`。补字脚本
   `tools/one-off/font_subset.py`（分片已删，需先从 git 历史取回；缺字走系统楷体回退）。
3. **首屏图 WebP**：16 张 PNG → WebP q86，991KB → 328KB（背景/心法卡底/流派横幅/武库/武学图标/弓玦图标）。
   引用集中在 `version.json` 的「界面图片」（短路径，相对 `assets/img/`）与 `web/studio.css` 两条 url()；
   `check:site` 第 9 项逐个验证存在。转换脚本 `tools/one-off/img_to_webp.py`。

**效果与边界**：本地二次打开基本 0 网络（SW 命中）；首次冷启动仍受跨境 RTT 限制
（字体 357KB + 首屏图 328KB + JS/CSS ≈300KB）。想再快 = 上 Cloudflare 橙云/迁 Cloudflare Pages
（可自定义 immutable 头），当前零构建方案不换。

**纪律**：新素材优先 WebP；大图必须压缩后再入库；改完引用跑 `npm run check:site`。
