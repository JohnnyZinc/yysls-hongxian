## 1. 站点是什么

「燕小叽」是燕云十六声的网页工具站，Vite 打包的 Vue3 SPA（Naive UI），路由：
`/`（首页）、`/AxisSimulation`（时间轴模拟 = DPS 计算器）、`/diy-panel`（DIY 属性面板）、
`/home`、`/more`、`/tools/*`（武学/心法/套装/周购/助手）。

**关键架构事实：游戏数据全部打包在前端 JS 里，没有数据 API**（API 只有招募/更新日志等站点内容）。
- 入口 `assets/index-*.js`（约 500KB）→ 模块表引出轴数据 chunk `assets/useTimelineAxisState-*.js`（约 1.3MB）
- chunk 内数据：技能 151 条、增益 69 条、**轴配置 36 条**（覆盖全部 11 流派，含多条历史版本）、
  技能/增益的 IR 字节码程序、槽位表
- 主包内还有：心法属性表（按 build×版本，如 `XF_STBY: 最小外功+130.1/直接会心+4.6%`）、
  定音/词条字典（如 `ZXDF_QZJPSJZS = 斩雪刀法·轻重击派生技增伤，maxValue 10.6×4 件`）

轴的作者署名 **by@Violetta**——与项目里 Excel 计算器（`EXCEL计算器/*.xlsx`）同一作者，属同源数据的不同载体。

## 3. 引擎怎么算（全解码）

### 3.1 逐事件输入 = 面板汇总 + 技能 IR + 各增益 IR + 轴全局

站点把每个技能/增益编译成一段**字节码 IR**（`{code, constants, maxStackSize, writtenOutputSlots}`），
由一个约 20 个操作码的栈式虚拟机执行，输出写入 41 个属性槽。操作码：

```
1=推常量  2=推输入槽(装备/面板)  3=推时间轴槽(层数/距离/能量/buff存在性)  4=推旗标(流派/武学/心法/套装/技能类型)
30=输出槽+=弹栈  31=输出槽=弹栈
20=三元选择  21=钳制  10~18=加 减 乘 除 min max == > >=
```

例如沧海帖：`TL(tieStack) → OUT[CRITICAL_DAMAGE] +=`（层数×1% 会伤）；
易水歌：`FLAG(心法:易水歌) ? YSGStack : 0 → COMMON_DAMAGE +=`，`FLAG ? YSGStack×2 : 0 → EXTERNAL_PENETRATION +=`。
每个技能还带 `if energy>1 then 会心伤害+21`（气竭）；横刀系技能带大段定音匹配逻辑（读装备定音分配槽）。

### 3.2 伤害公式（函数 Qx 管线，已完整移植核对）

```
① 三率 $s：
   生效精准 = clamp(精准,0,100)
   生效会心 = clamp(会心,0,80) + 直接会心
   生效会意 = clamp(会意,0,40) + 直接会意
   最终会心率 = 精准×(会心或(100-会意)) /100      （会心+会意>100 时会被意挤压）
   擦伤率 = (1-精准)(1-会意)                     普攻率 = 100-会心-会意-擦伤
② 攻击区间 Sh：min/max/mid=(min+max)/2；主属性分支叠加无相攻击；无相穿透并入主属性穿透
③ 增伤汇总 Nh/Ph：常规增伤 = 通用 + 首领 + 类型武学增(横刀/陌刀…) + 全武增（奇术技能只吃全奇术增）
④ 穿透 xh：(穿透-抗性)>0 ? (差)/2 : 差          （正穿透半价、负穿透全价）
⑤ 主公式 Mh：外功 base=(攻击-防御)×倍率；属性 base=攻击×倍率（不扣防御）；
   固伤×固伤加成另算；四态 = 会心(mid×会心伤) / 会意(max×会意伤) / 普攻(mid) / 擦伤(min)，
   各乘 常规增伤×分支增伤×穿透×定音×raid×特殊；
   期望 = Σ(四态×对应率)
```

与项目引擎（`engine/dps.js`，Excel L 列翻译版）逐项比对：

| 机制 | 站点 | 项目 | 结论 |
|---|---|---|---|
| 三率上限 100/80/40、会心×精准、会意挤压、擦伤=(1-精准)(1-会意) | ✓ | ✓ | **等价**（代数形式不同、数值一致） |
| 会心=中攻 / 会意=大攻 / 擦伤=小攻 | ✓ | ✓ | 等价 |
| 穿透正半价负全价 | ✓ | ✓ | 等价 |
| 增伤池相加（通用+首领+类型+全武） | ✓ | ✓ | 等价 |
| **属性固伤×1.5** | 无（×1.0） | 有（主属性 elem_flat×1.5） | **公式差异，约 -1.2% 总伤**（同数据实测站点公式 12,840,204 vs 项目 12,998,834） |
| 外功加成作用位置（作用在攻击值 vs 作用在整项） | 不同 | 不同 | 本项目数据外功加成为 0，无实际差异 |
| 定音粒度 | 按定音类型分配+匹配模式 | 单一「技能定音」值+技能标记 | 语义可映射（见 §5） |
| 强制会心/会意/精准 | SURE_* 槽，可带装备条件 | skill.force_* 静态标记 | 纯唐轴不涉及；双切轴蓄力技有「开山且有效会心≥75%→强制会心」的逐事件条件（工具暂不支持，见 §6） |

## 4. 与项目数据同源性验证（关键证据）

1. **技能倍率逐一相等**：站点 16 个纯唐技能与 Excel 3.0 包同项技能 ext_mult/elem_mult/固伤全部相同
   （横刀安西军(热血) 连 spec_bonus 0.4 都对得上；站点把 Excel 的占位名「横刀～/横刀Q1/横刀重击派生」

## 6. PoC 结果与差距清单

**已产出**：
- `tools/extract_from_site.mjs`——提取工具（自动解析站点当前 chunk → 提取数组 → 移植 VM 求值 → 生成三件套；
  带「技能 IR 含逐事件/装备条件」的安全校验，纯唐轴 16 技能全部通过）
- `data/schools/lieshijun/lieshijun.chuntang.115.3.0.{json,skills.json,effects.json}`——纯唐草稿包（114 事件/16 技能/31 效果）
- 全量测试通过（无回归；草稿包未接 manifest，不影响现有链路）

**DPS 验证**（项目引擎跑草稿包；2026-10-22 修正两处提取 bug 后重测）：

| 面板 | DPS | vs 站点基准 172,842 |
|---|---|---|
| 草稿默认（双切 Excel 面板 + 心法置换：会心 **74.59**/会伤 50） | **152,017** | **-12.05%** |
| 会心率顶满 80% | 156,143 | -9.66% |
| 会心 80% + 会伤 54%（双切作者值） | 159,085 | -7.96% |
| 会心 80% + 会伤 54% + 属性攻击 +7 条（站点配额） | 168,555 | **-2.48%** |
| 同数据下两引擎公式差 | — | **-1.22%**（属性固伤×1.5 所致） |

修正的两处提取 bug（均在本轮发现，影响上面所有数字）：
1. **心法三率未除判定抗性**。孤忠不辞 `CRITICAL_RATE=13.5` 走的是「除判定抗性前」的分子
   （`stats.会心率 = total(会心率)/jk`，jk=2.8），提取时却直接减在最终面板上 → 会心率被写成 65.91%，
   正确应为 79.41−13.5/2.8 = **74.59%**。修正后 DPS 145,401 → 152,017。
2. **`build.name` 写成了「裂石钧·纯唐轴」**。引擎拿 `build.name` 当流派名查 `version.武学天赋`，
   查不到就静默丢掉整套天赋（裂石穿透 30/裂石加成 15%/会心率 15%/裂石攻击 984）。
   默认面板不受影响（panel_input 覆盖），但**配额物化全盘受影响**：物化面板裂穿 6→36、裂加 NaN→15%、
   会心率 74.37%→79.73%，物化 DPS 由比默认面板低 15% 变成高 1.04%（与双切的 -4.27% 口径一致）。
   已改为 `name` 恒取流派中文名（工具内置 SCHOOL_CN 表），分支信息由文件名与 manifest 承载。

**差距清单（按严重度）**：

1. **作者参考面板不可恢复（唯一实质性差距）**。站点的 hundredDamage 是用**作者本人装备**算的；
   GOAT_KEY 只是「毕业率」打分参考（比作者装备弱），且只给了 mid 值（最小/最大攻击拆分、会心伤害、
   定音分配额均未公开）。因此 -8% ~ -16% 的差是面板参数差，不是提取错误。精确复现需要拿到作者装备，
   或逆向站点「快速添加」预设生成规则（预设数据在主包 index-Cd3ybpzz.js，未做）。
2. **工具不支持逐事件条件型技能贡献**。双切轴的陌刀蓄力技带「开山 且 有效会心≥75% → 强制会心 + 会心率+15」
   （读装备三率槽+buff 存在性），静态技能表表达不了；纯唐轴无此模式（工具已加校验，遇到会告警）。
   双切草稿包因此偏低估约 9.6%，已删除不留混淆。
3. **惧刃的 +8% 通用增伤有条件**。站点：仅「远·元素剑气」(YUAN_YSZJ) 类型技能享受，裂石钧技能无一命中 →
   草稿包惧刃只有四系穿透 16；Excel 3.0 是无条件 +8%。两作者模型差异，草稿从站点（更新）。
4. 前端包按内容 hash 命名，站点更新后 chunk URL 会变——工具每次自动解析当前 URL 并缓存到 `.cache/site/`，
   离线复跑可用 `--no-download` + 本地文件。

## 6.5 站点「最佳词条配比」与项目纯唐配额的差异（实测）

站点 `BEST_MAX`（键已确认 `MIN`=敏）与项目 `lieshijun.chuntang.xiaowai` 的**唯一差别是 2 条词条**：

| | 最小外功 | 敏 | 精准 | **会心率** | **属性攻击** | 横刀增 | 全武学 | 首领增 | 合计 |
|---|---|---|---|---|---|---|---|---|---|
| 站点 BEST_MAX | 12 | 8 | 3 | **5**（最大裂石5+最大无相2=7） | | 1 | 2 | 2 | 40 |
| 项目 chuntang.xiaowai | 12 | 8 | 3 | **7** | **5**（裂石/无相大小攻四选池） | 1 | 2 | 2 | 40 |

（站点拆「最大裂石5 + 最大无相2」只是槽位限制——引擎里无相攻击是**加算到主属性裂石上**的，
两者数值区间相同，等价于 7 条属性攻击。）

**结论：这 2 条词条不是那 8%~16% 差距的原因**，理由三条：

1. 那 8%~16% 比的是「草稿包默认面板 DPS」vs「站点发布基准」，**全程没有配额参与**。
2. 同一 build 包、同一物化流程下实测：**站点配比反而低 3.62%**（项目配额 153,598 / 站点配额 148,031），
   方向相反，不可能造成"我们偏低"。
3. 会心率词条的边际（项目物化面板）：单条约 +2.8%~3.4%；属性攻击单条约 +0.8%。
   2 条的量级只有 ±5%，撑不起 8%~16%。

**为什么两套配比会不同——谁更优取决于"非词条部分的会心率"有多高**：

会心率词条的最优条数 = **把面板会心率顶到 80% 上限所需的最少条数**，多一条完全浪费（实测第 9 条起边际 0.09%）。

| 面板起点（0 词条时会心率） | 顶满 80% 所需会心率词条 | 更优配比 |
|---|---|---|
| 项目物化面板 41.66%（含敏8） | 7 条（→79.73%） | **项目 7 + 属性 5** |
| 作者面板（推测更高） | 5 条即可 | 站点 5 + 属性 7 |

即：站点作者面板的非词条会心率比我们的物化面板高约 11pp（站点配比 5 条只到 68.85%，差 11pp 才满），
这正是"作者装备未公开"的又一体现。**在当前项目的面板口径下，项目的 7 条是对的**；
若将来拿到作者真实面板，需按同样规则重算会心率条数。

## 7. 结论与建议

- **可以提取**。数据同源（同一作者 Violetta）、字段 1:1 可映射、公式偏差 -1.22%（已定位到属性固伤×1.5）、
  跨源基准互洽 0.008%。PoC 草稿包已生成并通过全量测试。
- **建议路线**（按优先级）：
  1. 短期：草稿包先不接 manifest。若要用，把 `lieshijun.chuntang.115.3.0` 加进 `data/version/manifest.json`
     的 build包（`{id, 流派:"lieshijun", 分支:"chuntang"}`）、跑 `npm run build:index`、在
     `tools/test_dps.js` 的 BUILDS 加一项并用站点基准（总伤 15,452,053.73 / 89.4s）做金标准；
     面板默认值建议改为从纯唐方案配额物化生成（`computeGraduateDps`），比继承双切面板更自洽。
  2. 中期：若要逐位复现站点 DPS，逆向站点「快速添加」预设（含词条/定音生成规则）拿参考装备；
     或等 Violetta 发布纯唐 Excel 计算器，走 `extract_calculator.py` 原教旨路线（0.0000% 逐事件校验）。
  3. 引擎层面：评估是否把「属性固伤×1.5」改为可配置（站点无此项），或在文档中固化为两引擎已知偏差。
- **运维提醒**：站点数据随版本更新（当前 `115_NLXH_UP` 南吕相和-上半，导出于 2026-10-16），
  换季/版本更新后需重跑提取并比对 quota/达标线变化。

## 8. 追加：管线自洽性验证（2026-10-22 晚）

为回答"纯唐包的 −12% 是不是包本身的问题"，补做了一组决定性对照：
**用同一条提取管线去提取站点自己的「裂石钧双切115竞速表」**，看它能否复现站点双切基准。

### 8.1 结果（build 包自带作者面板，不经方案物化）

| 包 | 来源 | 项目引擎 DPS | 站点发布基准 | 偏差 |
|---|---|---|---|---|
| `lieshijun.shuangqie.115.3.0` | Excel 提取 | 183,893.43 | 183,878.46 | **+0.01%** |
| `lieshijun.shuangqie.site115.3.0` | 站点提取（对照样本） | 166,268.14 | 183,878.46 | **−9.58%** |
| `lieshijun.chuntang.115.3.0` | 站点提取 | 152,017.33 | 172,841.76 | **−12.05%** |

**结论：提取管线本身有约 −9.6% 的系统性缺口**——连双切都复现不了，不是纯唐轴独有的问题。
两包 panel_input 完全一致（提取时 `--panel-from` 继承），差异不来自面板参数；
Excel 包 40 条效果 vs 站点包 33 条，但缺失的 10 条（惊神/烁鼓/扶风/裁云 等"拐"+笛+食物+鬼掣帖）
实测只值 **−0.30%**；惧刃 +8% 值 **−4.49%**；剩余 ≈ −5pp 尚未定位（疑似逐事件条件类机制未移植）。

### 8.2 同源包的公平对照（这才是判断"纯唐轴对不对"的指标）

| 对照 | 纯唐/双切 | 与站点关系 −6.00% 的偏离 |
|---|---|---|
| 站点发布基准 | −6.00% | — |
| 都用**站点提取包**、作者面板 | **−8.57%** | **2.57pp** |
| 上者 + 双方都带惧刃 +8% | −9.28% | 3.28pp |
| 纯唐站点包 vs **Excel** 双切包 | −17.33% | 11.3pp（不公平，包来源不同） |

→ **纯唐轴本身基本正确**（同源对照只差 2.6pp）；此前"差 10pp"的错觉来自拿站点提取包与 Excel 包硬比。

### 8.3 两个调参假设的实测（用户提出）

| 假设 | 效果 |
|---|---|
| 给纯唐加惧刃 +8% | 152,017 → 157,635（**+3.73%**）；vs 站点 −12.05% → **−8.80%** |
| 物化改按**满值** | 双切 −12.50% → **−8.69%**；纯唐 −21.45% → **−18.26%**（各改善 3~4pp） |

两者方向都对、都有效，但**量级都不够**：加 8% 只贡献 3.7pp，满值只贡献 3~4pp。
满值确实更接近站点基准，侧面印证**站点发布基准大概率是按满值（或接近满值）算的**；
但双切满值后仍差 8.69%，说明还叠加了"作者本人非词条面板参数"这一层。

⚠️ 注意加 8% 的**副作用**：8% 对双切轴的边际（+4.51%）大于对纯唐轴（+3.73%），
加了之后"纯唐/双切"与站点 −6.00% 的关系反而偏离更远（2.57pp → 3.28pp）。
加 8% 的价值在于**与既有 Excel 双切包口径统一**（作者按"队里有裂石钧队友"假设），
不在于消除与站点基准的差距。

### 8.4 遗留

- 管线 ≈ −5pp 缺口未定位（扣除惧刃后）。定位需站点逐事件伤害表（站点只公开总伤），
  可行路径：用浏览器打开站点该轴读逐事件表，或等纯唐 Excel 计算器发布。
- 对照样本 `data/schools/lieshijun/lieshijun.shuangqie.site115.3.0.*` 保留在仓库中
  （**不接 manifest、不参与测试**，仅作管线自洽验证的基准样本）。
- 接纯唐包进 manifest 前：golden 基准应用项目引擎实测值，不要用站点发布基准
  （否则会把 −12% 的管线缺口固化成"未达标"）。

## 9. 纯唐轴已接进项目（2026-10-22 晚，用户拍板）

**决策**：不再追求复现站点基准。本项目的毕业基准由方案模板计算（`computeGraduateDps`）而非写死，
只要纯唐 build 包本身没问题即可；承音值口径**不变**（不动满值）。

| `data/golden/dps-lieshijun.chuntang.115.3.0.json` | 新增黄金快照（dps 152,017.33 / 总伤 13,590,349 / 114 事件） |

**11 流派 12 个 build 包，再无缺轴分支**；borrowed/missing 降级路径保留作兜底。

### 比较边界（用户 2026-10-22 明确，勿越界）

- **毕业率 / 毕业基准只在「同流派 + 同分支 + 同方案」内比较**。跨分支、跨流派比较对玩家装备评价**无意义**
  （两者的方案、目标属性、技能轴都不同），**不做，也不要把两者的数值差当 bug 修**。
- 跨分支 / 跨流派的 DPS 只有一种用途：**观察游戏本身的流派平衡性**（当前版本下、理想装备中谁更强），
  属于另一回事，与装备评价无关。
- 因此 §8 里那些"纯唐/双切比值"**不是验收标准**，只是判断"提取管线有没有系统性漏东西"的**交叉验证手段**
  （拿同源包互比，抵消口径差）。纯唐包的验收标准是：
  事件完整、技能倍率与同源 Excel 一致、引擎跑通、同分支内毕业基准可生成——**四条均已满足**。
- 纯唐毕业基准（承音物化）：小外流 135,773.52、大外流 132,380.24；该数字只在纯唐分支内部有意义。
- 站点发布基准（172,841.76）仅作为 build 包 `graduate_dps` 的对照信号，不参与毕业率计算。
