# 2026-10-29

## 落地：全局感知转律建议（第一步，引擎 + 测试，未碰 UI）

新增 `engine/advisor.js`：
- `stateOf(prescription, slotName, item)` — 只评当前词条档位（不枚举转律），比 gradeItem 轻；与 gradeItem 同口径（按 weaponType 只匹配本类型槽）。
- `adviseConversion(prescription, slotName, item, opts)` — 全局感知转律建议。
  - opts：`gear`（当前整套装备，含本件）、`flow`（方案配额）、`dpsOf`（可选 `(gear)=>number`，注入式保持引擎纯粹）、`deadZone`（默认 0.005）。
  - 流程：定位本件 → 枚举（调律位 × 转律池目标，尊重已转律标记）→ 用 `quotaCensus` 算全局缺口 → **只保留严格减少缺口的** → 取 gap 最小（并列）→ dpsOf 决胜 → 死区内并列列出。
  - 返回 `{tier,k,m,gapBefore,gapAfter,suggestions[],并列,dpsBefore}`；suggestion 含 `from/to/position/kind/tierAfter/gapAfter/dpsGain`。
  - `kind`：**结构型**（当前非天 → 转后天）／**优化型**（当前已天档，转后更适配全局）／改善型。
- `advisor.js` 新增 `import { quotaCensus } from './monitor.js'`（monitor 只依赖 quota，无循环）。

新增 `tools/test_conversion.js` **28/28**，已并入 `npm test` 链（test_advisor 之后）。覆盖：唯一解、拆东墙不给、结构型、DPS 决胜、死区并列、已转律标记、参数缺失、stateOf/gradeItem 口径一致。

真实 DPS 端到端验证（鸣金虹 110 阶轴 + 115 赛季，materializeGraduateGear 造基准）：
- 天档场景：剑 大外/大外/剑增/劲/势 → 等阶**天**，全局缺口 1→0，建议「劲→会意率」**优化型**，DPS +5047（+4.77%）。
- 玄档场景：剑 大外/大外/剑增/劲/敏 → 等阶**玄**，缺口 2→1，4 个并列被 DPS 收敛为 1 个「敏→会意率」**结构型**，DPS +6848（+6.55%）。
- 性能：含真实面板+DPS **13~14ms/次**。

⚠ 教训：验证时装备件必须带**数值**（词条区间承音值），只有属性名时面板读不到数值、所有候选 DPS 相同，会误以为"DPS 决胜无效"。用 `materializeGraduateGear` 造基准最省事。

## 第二步 UI（已完成）

`web/studio.js` 详情页四条信息（用户定稿顺序）：
1. **当前方案的当前品阶**（直接展示，原有）；
2. **当前方案的转律建议**（直接展示，`conversionHtml`）；
3. **跨方案的品阶**（折叠，`<details class="st-xflow">`）；
4. **跨方案转律建议**（折叠，同上）。
- 措辞：**结构型/优化型不区分文案**；**并列项平铺**（不折叠）。
- 背包/新录入件用 `gearWithPiece(piece)` = "假设穿上"的整套（顶替同部位，武器按同类型；空位则追加）——否则 adviseConversion 在 equippedList 里找不到本件。
- 跨方案懒加载：`XFLOW` 缓存全流派方案（首次展开才拉，22 个方案推导约 0.5s，有"加载中…"占位）；`bindCrossFlowOnce()` 在 `renderModal` 外层包装里绑 toggle。
- 跨方案只做**单件视角**：`routesToTier` + `surveyFlows`，不算全局缺口、不算 DPS（跨流派 DPS 不可比）。武器件只评"该流派携带此类型"的方案。
- 实测（鸣金虹天档环）：22 方案中 0 个当前即天档、5 个转律可达天档、其余 17 个不提醒 ✓
