## 红线（改了会坏）
1. **存档 key 恒为 `yysls-evaluator-v1`**（现 v3 多角色）。改名 = 清空玩家装备库。
2. **`build.name` 恒为流派中文名**：引擎拿它查 `version.武学天赋`，查不到会**静默丢整套天赋**（配额全盘错）。
3. **心法三率分子是「除判定抗性前」**：`会心率 = total/jk`，**jk = 2.8**；扣心法贡献时三率须 `/100/2.8`。
4. **毕业物化数值 = 承音值（≈max×94%，标 `承音:true`）**，勿改回满值（满值下 22 方案 17 个三率溢出）。
5. **毕业基准 = 配额的一个可行解**（贪心填空、不算伤害），非最优 ⇒ 方案可能 >100%，**设计意图，勿当 bug 修**。定音不纳入优化。
6. **三率上限权威源 `version.constants`**（精准 100 / 会心 80 / 会意 40），`monitor.js RATE_CAPS` 只存键位，UI 从同一张表 import，禁止另写数字。
7. **`weaponType` 必须传进引擎**；`toGradeItem()` 漏传会漏判天档。游戏武器**不分左右**，key = `武器1`/`武器2`，禁止「左右武器」表述。**武器 = 类型桶**（桶容量 = 该类型出现次数，双枪=枪桶2）：桶内无序、替换要**遍历试换取 Δ 最优**，`gearAfter` 按索引移除、**不能用 `filter(sameEquipKey)`**（会一次删两把）。
8. **切角色顺序**：先 `save()`（charId 还是旧的）→ 改 charId → `applyChar()` → `switchSchool` → **必须 `refreshGraduate()`**（反了清空旧角色 / 沿用上个角色基准，都踩过）。
9. **`rebuildGear()` 是装备视图唯一重建入口**；`equipped`/`backpack` 都是派生视图；同一件可被多个配置同时穿（设计意图）。
10. **新增常量/清单一律入 JSON，勿在引擎写死**；语义布尔一律查表派生，禁止手写布尔字段。
11. **CSS 注释里不能出现 `{}`**：`cssBlock()` 用 `indexOf('}')` 截规则，断言会被截断。
12. golden 是防回归底线，偏差查根因，**不许改基准洗绿**。
13. **套装键名双层（2026-10-30）**：方案文件 = `攻具套装`/`防具套装`/`弓玦套装`；但存档 `state.selections` 与版本包攻具属性表**仍叫 `装备套装`/`弓玦`**（v3 存档兼容 + 引擎 optSource），**绝不许跟着改名**。防具套装 = 新 selections 键，`version.防具套装` 表效果暂为空（防具套只给气血等非 DPS 属性），不进面板；**13 套与攻具同数**（易相/鹰扬/玄甲/不知寒/梨雪/鸣珂/江凝/抱玉/尚义/盈盏/桂月/凌波步/御无缺）。

## 领域三层（用户亲自定义）
**流派**（武学天赋/武库/武学/两把武器）→ **分支**（打法→技能轴→心法→配额）= build 包，一一对应 → **方案**（大外流拉单次上限 / 小外流求稳定）。
方案文件字段 = `流派`/`分支`/`方案`；`_meta.json` = 中文名 + 分支表 + `武器`；`manifest.json` 两级 `流派[]` + `build包[]`。`flowId` = 「分支.方案」（存档键）。

## 等阶 / 处置 / 转律（2026-11-01 大修，权威版 = `评价系统设计.md` §11）
- 四档：天=k0m0 / 地=k0 且 m≥1 / 玄=k=1 / 黄=k≥2（k=废词条数，m=必备缺几条）；**只看结构不看数值**，按当前词条评，不含转律。**`tierAfter='天'` 不许渲染成当前天阶**（只是潜力）。
- **处置四分类**：直接穿上 / X转律为Y后穿上 / 放背包 / 分解回收（+退化态「信息不足」= 拒绝回答，非第五类）。**地档也放背包**；放背包**大概率是同档候补**，不是低一档。
- 规则链有序：空位→直接穿上；`Δ转后`超死区且>Δ现状→转律后穿上；当前档>已穿档→直接穿上；同档且Δ现状超死区→直接穿上；档∈{天,地}→放背包；其余→分解。
- **档位优先 = 配额优先**（就是 (k,m) 字典序）。**DPS 只在同档破僵局**，不能当主序；天档 DPS 负也照穿（可承音修复、不可再生）。
- **转律门槛 = `Δ转后` > `Δ现状`**（「转后必须到天阶」已废：实测转后到天但净损 2pp）。**潜力只在值得兑现时展示**。另加**结构不可退化**：转后 (k,m) 任一变大直接否决，哪怕 DPS 更高。
- **转律试算按目标词条重取数值**（承音值优先）；沿用被转掉那条的数值会让候选 ΔDPS 反序（`prescription._affixes` + `transform.transformedItem`）。
- **转律是否强制看全局（2026-11-01 玩家定稿）**：`全局必需 = 必修 || relief 非空`（relief = 转律前后**按行**比 `quotaCensus` 缺口，缺口变小的行）。全局必需 ⇒ 必须建议转并说明"直接穿会少哪一条"；否则转律只作附注「转不转取决于你」。**降幅超死区时必须写"用伤害换配额"**。没传 `flow` 则退化回旧口径。
- **转律不许「换洞」**：① `noNewRequiredGap` 按词条身份比本槽必备缺口（只看 m 看不出「洞从 A 挪到 B」）；② `noRowWorse` 行级 Pareto（任何一行缺口不许变大，只看总数看不出挪洞）。两处同步：`dispose.bestConversion` / `advisor.adviseConversion`。
- **转律门槛第三条：转后档位必须 ≥ 地**（玄→玄一律不建议，烧材料+三天 CD 换不来档位）。两处同步：`dispose.bestConversion` / `advisor.adviseConversion`。
- **已穿戴件走 `disposeWorn()`**：动作 `留着 / 转律后继续用 / 可以分解`，前缀 `这件装备已经穿在身上，`，**不跟自身比较**。
- **跨流派方案名要中文**：`META_BY_SCHOOL` + `ensureAllMetas()` 预热；`configLabelOf` 优先用 `XFLOW.entries[].label`（`state.meta` 只有当前流派，直接查会退化成拼音）。
- **转律目标两条硬约束**：目标必须在配额需求集内（`demandAffixesOf`）；有废词条时只转废的那条。
- **规则 1（转律后穿上）带档位门槛：`转后档 ≥ 已穿档`**（2026-11-02 玩家实测补上，用 `>=` 不是 `>` —— 转后同档允许）。只有 `Δ转后 > Δ现状` + `全局必需` 就放行的话，会出现**身上天阶、这件玄阶、转后地阶，还建议"转律之后穿上"** —— 为了补一条配额降两档。档位就是 (k,m) 字典序，降档说明结构更差。拦住后落规则 4 → 放背包。
- **转律目标排序 = 可行性 → 必修 → 缺口 → DPS**（不是 DPS 主序）。可行性用 `verifyGearFits`（钉住全包已穿件）判，不能用 `verifyItemFits`（只钉一件、其余自由重规划，答不出"剩下空位塞不塞得下"）。`必修 = 有空槽 && 转后可行 && 转前不可行`。
- **处置唯一出口 = `engine/dispose.js disposeItem()`**（§11.3 六条规则链 + 跨方案兜底降级为放背包）；**组合总览唯一出口 = `engine/search.js searchBestComposition()`**（`score=(缺口,溢出,−DPS)` 字典序）。UI 里别再另写判定，两处口径必须一致。
- **DPS 只在别无他法时出现（2026-11-01 玩家定稿）**：配额或档位能决定的事，文案里**一个伤害数字都不许有**；只有同档之争、可选转律（唯一依据）才报。旧版「用伤害换配额」已删。
- **录入表单与详情页同一套出口**（2026-11-02）：`disposeItem`/`disposeWorn` + `disposeSayHtml`；没录满只给一句潜力话。旧「更好/更差/等价 + 三向建议」已废。按钮主次跟 `disp.action`；编辑模式只留「保存修改/取消」、`ed-slot` 带 `disabled`、调律候选按其他位过滤。
- **处置句四段式（2026-11-02 定稿，勿回退）**：① 品相 + 对比身上那件 + 谁更高（`老大，这件{词条}，X阶品相。而你现在穿的这件是Y阶品相。` + `还是你身上那件更好些。/这件比你身上那件强。/两件一个档。`）② 还被别的方案用着（`不过…`，**"也不是一无是处"只在别处档位更高时**才说，否则只陈述）③ 转律（`要穿它的话，…`，含转后能到几阶）④ 结论（`总之，{动作}；另外 N 套里它也是件好东西。`）。**②③可缺，①④恒有**。已穿戴件段①末尾换成`它正穿在你身上。`、且无对比。拆四段的原因：两段式时"这件装备"接在"你身上那件"后面会指代不明。
- **详情页最终形态（勿回退）**：`词条表`（背包件+同部位有穿戴 → 两张并排表，见下条） → `处置` = **四段话**（见上条；品相按档着色；**建议不整句加粗**，只有「N 套」是金色链接） → `其他方案（折叠）`。**「词条」段可点，点开显隐 `.st-say-detail` 明细（缺哪些必备/哪条无效/宫位不能转律），点击只切 hidden 不重渲染**。已删除且勿加回：判定徽章、面板变化表、独立转律建议块、依据折叠。句子由 `engine/dispose.js` 的 `parts` 产出。
- **处置句两处同源 + 字段名（2026-11-02）**：`parts` = `词条/已穿档/穿在身上/高下/使用中/转律/结论/跨方案`；`对比`/`建议`/`前缀`/`附注` **已废，别再引用**。`高下` 由 narrator 用 `rankOf` 算；`穿在身上` 由 narrator 参数传（`disposeWorn` 传 true）。改句式必须**引擎 `compose` 与 UI `disposeSayHtml` 两处同步**。上色与链接化用 UI 的 `rich()` 在**同一次 escape 之后**做完 —— 拆成 `tierify`/`linkify` 两个函数套用，前一步的 `<b>` 会被后一步转义掉。

## 立绘（2026-11-03 落地；原「周黑线」章节见下）

- **形象以玩家给的参考图为准**：双髻红发带蝴蝶结、粉纱格纹短外衫、白长袖、紫色绣花挎包、深蓝云纹长裙、暗红布鞋。**没有红披风**（那是 wiki 剧情设定，上一版提示词凭文字想象写错了）。`立绘提示词.md` 是出图提示词 + 现状表。
- **抠图由玩家/外部工具做，脚本只管归一化 = `tools/normalize_portraits.py`**（2026-11-03 玩家嫌自动抠得糙，改用他抠好的成品）：
  输入 `素材库/周红线/抠图/*.png`（RGBA）→ 按 alpha 包围盒统一缩放 1180px 高 → 脚底对齐同一基线（画布 1300、脚底留 18）→
  **按头部中心**（顶部 10% 中点）水平对齐 → 四张统一放进 **410×1300** 画布 → 出 `web/assets/img/char/*.webp`（~95KB）+ `manifest.json`，无损 png 母本进 `素材库/周红线/_抠图/`。
  **四张必须同宽同高**：尺寸不一致时 CSS 按右缘定位会横向漂移；对齐用头部而不是裙摆 —— 换表情时玩家的眼睛盯着脸。
  `tools/cutout.py` 只适合纯白底原图（自动抠），成品抠图别走它。
- **画布尺寸要可预期**：早期画布留了大片透明（800 宽、人物只占 400），前端按 width/height 算出的比例失真，人物永远显得很小、怎么调 CSS 都不对。现在固定 410×1300，`width:38%` 就是人物宽度。
- **DOM**：`.st-assist-face` 是**绝对定位背景层**（`inset:0; z-index:0; pointer-events:none`），面板其余子元素 `position:relative; z-index:1`。五张图叠在同一位置，靠 `[data-mood]` 切 `opacity` 交叉淡入 —— **不许换 src**（会闪白）。
- **桌面不叠任何遮罩/渐变**（2026-11-03 玩家定稿）：图是抠好的透明底，文字也已让开右侧，再压 mask 或墨纱就是白糊一层。`mask-image` 与 `.st-assist-face::after` 的渐变**只写在移动端媒体查询里**；base 规则里 `::after` 只保留 `content:''; inset:0`（移动端要用这个伪元素）。
- **桌面：立绘高度 = 对话框高度的 2/3**（`--pt-h: 66%` + `.st-assist-portrait { height: var(--pt-h) }`，右键改这一个值；想改比例**同时改 `--pt-hc`**）。**别按栏宽定尺寸** —— 之前写 `width:38%`，窗口越宽立绘越高，1920 下占面板 94%，头顶直接顶到「设置/收起」那一行（玩家实测报的）。宽度由图片比例 410:1300 自动推出。
- **文字避让宽度必须以高度为基准**：`padding-right: calc(var(--pt-hc) * 0.315 + 22px)`，`--pt-hc: 66cqh`，靠面板上的 `container-type: size` 才有 `cqh`。用 `%`（相对宽度）在宽屏上会避让过头。
- **移动端 = 整屏背景 + 对话贴底**（2026-11-03 玩家定稿）：立绘 `height:100%` 居中、脚站到底；`::after` 竖向墨纱从 **28% 开始压深、48% 已 .82、62% 近乎实心**；`.st-assist-flow { flex:0 1 auto; margin-top:auto; max-height:46%; justify-content:flex-end }` —— 消息**从腰线往下堆**，内容多了在 46% 封顶内滚，**永不压到胸口以上**。所以「名字 + 设置/收起」这一行要 `order:2` 挪到消息下面（原来的顶部位置会压在她头顶）。**别做「脖子以上全透」**——试过，画面直接成了无头人，玩家会当成 bug。
- **情绪只有四张图（angry 待出）**：等模型/思考链=`think`、首段正文=`talk`、追问部位/报错=`unsure`、「不理你/哼」=`angry`。清单里没有的情绪**自动回落 idle**，补图只加文件不改代码。
- 状态机纪律：思考链阶段**只升不降**（reasoning 很长，按「谁在流式」判断会让一张脸在一句话里闪两三次）；说完 `restMood()` 2.6~3.2s 回 idle。

## 助手「周黑线」（2026-11-02 骨架；人格/立绘仍是占位）
- **三栏只认一个开关**：`.studio.assist-on` + `repeat(3, minmax(0,1fr))`（固定像素的 `--assist-w` 已废）。≥1600 默认展开，<1200 她全屏 + `#st-dock` 三视图，桌面收起后靠 `#st-assist-toggle` 叫回。
- **右栏三个子元素都是 `.st-panel`**（口径 / 心法 / 主面板），主面板认 `id="st-main-panel"`；用 `#st-right > .st-panel` 一概而论会把口径和心法也拉起拉伸。
- **装备槽/背包不许写死像素宽**（`.st-slots` / `.st-backpack` / `.st-config-note` 一律 `width:100%; max-width:780px; margin:0 auto`）。写死 660 时左栏越宽两侧空白越大（曾到 96px，比 28px 的槽间距还大），而且背包与装备槽对不齐。

- **她只当嘴不当脑**：事实只来自 `compactFacts()`，模型不许推算数字；规则能认的意图（`intentOf`）不过模型；工具只出卡片、不改状态。没 key / 断网 / 模型报错一律回落模板话术，**不许让工具因此不可用**。
- **对话历史可以直接丢，不做摘要、不做"新对话"按钮**：事实活在引擎里、不在对话里，截断照样答得对。按跨天 / 切流派 / 超 40 条自动分段。
- **主动提示去重按「件 uid × 结论签名」，不按时间窗**（连录多件都要能各说各的）；开口只有三种：件值得动 / 背包凑出更优组合 / 可转律补齐缺口（第三种未接）。
- **组合提示必须防抖 + 切配置期间静默**（2026-11-02 实测 bug）：`pickConfig` 先 `switchBranch` 再 `switchPlan`，中间那次 render 的 equipped 是空的（新分支的 loadout 还没建），搜索会把背包里随便什么件都当成"能换"；等最终态一算却是「已最优」，玩家看到的建议全是错的。现做法 = `state.switching` 期间 `maybeNotifyComposition()` 直接 return（不记基线不开口），`finally` 里再统一判一次；另外 600ms 定时器里要**重新读一次 `state.search.result` 比 sig**，对不上就作废。
- **切换配置一律走 `actions.gotoFlow(school,branch,plan)`**（一个动作切完，内部 `state.switching=true`）。流派弹窗是两级：`state.schoolPicker = null | {school:null} | {school:id}`，一级印章网格（角标=该流派几套配置），二级分支·方案列表；**单配置流派点印章直接切**。数据复用 `XFLOW.entries` + `flowsOfSchool()`，首次打开先 `ensureCrossFlows()`。**不要再写「先切流派再切方案」的两步入口** —— 中间那个真实状态会让助手说错话。

- 知识库 `data/kb/*.md` + `index.json`，front-matter 的 `title/tags/summary` 就是索引；机制类只许照片段说、检索不到答"拿不准"，经验类可自由组织。
