# 项目长期约定（yysls 燕云十六声装备评价工具）

> 只记「不可推导的决策 + 踩过的坑」。逐轮细节见 `.workbuddy/memory/<日期>.md`。

## 架构支柱
- **1 引擎 + N 流派数据**：流派差异全在 JSON。换季 = 复制 `data/version/<赛季id>/` + 改 manifest；接流派 = manifest 加一条 + `data/schools/<前缀>/` 三件套。**新增常量/清单一律入 JSON，勿在引擎写死**。
- **毕业基准由方案计算**：`computeGraduateDps`（配额物化）生成；`build.graduate_dps`（Excel I16）仅兜底。
- **毕业物化数值 = 承音值**（≈max×94%，标 `承音:true`）。勿改回满值（满值下 22 方案 17 个三率溢出）。定音无承音字段，取 max。
- **毕业基准 = 配额的一个可行解**（`solveAssignment` 贪心填空，不算伤害），非最优 → 多选池方案可能 >100%。**设计意图，勿当 bug 修**。**定音不纳入优化**。

## 领域三层（用户亲自定义）
- **流派**（武学天赋/武库/武学/两把武器相同 ≈ build 包前缀）→ **分支**（打法→技能轴→心法→影响配额）→ **方案**（大外流拉单次上限 / 小外流求稳定）。**分支 = 技能轴 = build 包，一一对应**；牵丝霖两分支共用 `qiansilin.115.3.1`。
- **已落地（勿回退扁平）**：方案文件字段 = `流派`/`分支`/`方案`/`攻具套装`/`防具套装`/`弓玦套装`/`武库`/`心法`（2026-10-30 起套装字段更名：`装备套装`→`攻具套装`、`弓玦`→`弓玦套装`，**新增 `防具套装`**——`version.防具套装` 表效果暂为空对象（防具套只给气血等非 DPS 属性），不进面板；选择模态框四区）。**`version.套装简称` = 26 条全称→单字映射（徽标用简称、title 用全称；版本包键是「急风骤」非「疾风骤」→ 风）**；`data/template/<流派>/_meta.json` = 中文名 + 分支表（中文名唯一来源）+ `武器`；`manifest.json` 两级 `流派[]` + `build包[{id,流派,分支}]`；`version.json.方案类型` 派生小外流。**语义布尔一律查表派生，禁止手写布尔字段**。
- **⚠ 套装键名双层**：方案文件叫 `攻具套装`，但版本包属性表和 `state.selections` 存档键**仍叫 `装备套装`/`弓玦`**（引擎 optSource 按老键取值，v3 存档兼容）；UI 显示文案用「攻具套装/弓玦套装」，存档键不许改。
- `flowId` 恒为「分支.方案」（存档键）。`resolveBuild()` 返 exact/borrowed/missing，missing 时 `state.data=null` 走错误视图。补包 = 纯数据操作，零改码。

## 存档 / 多角色 / 装备库
- **存档 key 恒为 `yysls-evaluator-v1`**，改名=清空玩家装备库，**绝不可改**。现 v3。
- 装备、流派、分支方案、口径（心法/套装/弓玦/武库）**全部按角色隔离**：`{版本:3, 当前角色, 角色:{[id]:{name,school,branch,plan,selections,pool,loadouts}}}`，顶层冗余一份当前角色旧字段。入口 = 顶栏角色按钮 → `state.charPicker`。不许删最后一个。
- **切角色 `switchChar(id)` 顺序**：先 `save()`（charId 还是旧的）→ 改 `state.charId` → `applyChar()` → `switchSchool(...)` → **必须 `refreshGraduate()`**。⚠ 先改 charId 再 save 会清空旧角色；漏 refreshGraduate 会沿用上个角色的基准（都踩过）。
- **配置级已穿戴**：配置 = 流派+分支+方案，各存一套；没配过的切过去槽位为空（预期）。`pool`（角色唯一库，uid 唯一）+ `loadouts:{'流派|分支|方案':{槽位:uid}}`，`configKeyOf()` 用 **|** 分隔（流派 id 含点号）。
- `equipped`/`backpack` 是**派生视图**；**`rebuildGear()` 是唯一重建入口**。**同一件可被多个配置同时穿**（非独占，设计意图）。删装备走 `removePieceFromPool(uid)`。
- 旧档迁移：**先存储键归一（左/右武器→武器1/2）再入库**，且先全量扫 uid 再发号——反了整批丢装备。

## 引擎 API
- `computePanel({version, affixes, build, gear, selections})`：**`affixes` 必需**（武器类型清单与属性攻击键由它派生）。
- `canonicalAffix`/`quotaCensus`：别名表须显式传 `aliasMapOf(affixes)`，无模块级默认值。词条元数据访问器都在 `engine/quota.js`，UI 与 graduate 共用。
- `calcDPS`：三率上限由 `version.constants` 传入，**上限在 dps.js 内已 clamp** → 超上限自动 0 收益。`stateOf()` 只评当前词条档位，与 `gradeItem` 同口径。

## 等阶 / 处置 / 转律建议（定稿；2026-11-01 大修，权威版 = 评价系统设计.md §11）
- **等阶只有天地玄黄四档**，按**当前词条**评定、不含转律；转律另写「把「X」转成「Y」，等阶 玄 → 天」，字段 `tierAfter`。**禁止把 `tierAfter='天'` 渲染成当前天阶**（它只是「有天阶潜力」）。
- 标准：天=k0m0 / 地=k0 且 m≥1 / 玄=k=1 / 黄=k≥2。**k=废词条数**（不在该部位池或配额里没这条）；**m=该部位必备缺几条**。只看结构、不看数值（roll 不入档是既定设计）。
- 潜力与匹配度对**已录满**的装备必须同档；未录满才 = 空位最优填充 + 至多 1 次转律的可达档位。
- **毕业率/DPS 一律不展示给单件**：只报 更好/更差/**等价**（`swap.js verdict`；"等价"是二次确认用词，勿改回"相同"）。
- **处置四分类**：直接穿上 / X转律为Y后穿上 / 放背包 / 分解回收。**规则链有序**（先命中先返回）：空位→直接穿上；`Δ转后`超死区且>Δ现状→转律后穿上；当前档>已穿档→直接穿上；同档且Δ现状超死区→直接穿上；档∈{天,地}→放背包；其余→分解。
- **档位优先 = 配额优先**（天地玄黄本身就是 (k,m) 字典序，同一件事的两种说法）。**DPS 是第二层，只在同档（k、m 完全相同）破僵局**——不能反过来当主序。地上的 DPS 负值也照穿：天档 DPS 低可修复（承音抬数值、其他部位补三率），天档本身不可再生。
- **放背包 ≠ 低一档候补**：更大概率是**同档候补**（同部位两件天，一穿一备）。**地档也放背包**。
- **转律建议门槛 = `Δ转后` > `Δ现状`**（旧门槛「转后必须到天阶」**已废**：实测地档缺劲件现状 +3.28%，转「会心率」→「劲」后掉到 +1.29%，转后到天但净损 2pp）。救废型（k↓）收益必然为正；补缺型（k 不变、m↓）必须过 DPS 关。**潜力只在"值得兑现"时展示**，否则会诱导玩家亏材料。CD = 装备级/可重转/成本低 ⇒ 每件独立判断，不做跨件分配。
- 分档**唯一用途 = 处置建议**，不是强度排名。**位置命名**：宫=初始位，商/角/徵/羽=四条调律位；转律徽章写「转」、放**词条名前**。

## 处置 / 转律 / 组合搜索（2026-11-01 实现）
- **`engine/transform.js`**：`transformedItem(item, {index,to}, affixes)`（单条转律后的件，数值按目标区间重取承音值）+ `toGradeShape(piece)`（装备件/评价对象 → gradeItem 入参）。三个消费者共用：advisor / dispose / search。
- **转律试算必须按目标词条重取数值（2026-11-01 第四次修正，严重）**：只改 `属性`、沿用原 `数值` 会让「小外 131.2→敏」用 131.2（虚高 58%）、「外防 65.6→敏」用 65.6（虚低 21%），**两个候选 ΔDPS 反序**（实测 +2.04%/+1.71% vs 正确 +0.93%/+2.12%）。`adviseConversion` 现用 `retune()` + `transformedItem` 逐位重取（数值同则保留玩家实测值）；`prescription._affixes` 挂原始词条表供下游取用。
  - 附带发现：**敏 > 大外** 的主因是**五维达标率 0.9557→1.0**（不是攻击数值）。外防→敏 +2.12% > 外防→大外 +1.18%，面板侧小外 2390.8→2471.3、大外不变。
- **转律目标两条硬约束**：① 目标必须在**配额需求集**内（`demandAffixesOf` = 配额行 any_of 并集）——转成"会意率"这种配额里没有的词条不减少任何缺口，只是把废词条换成另一条零贡献词条；② **有废词条时只转废的那条**（`k>0 && from ∉ 无效调律 ⇒ skip`），否则会建议"转掉会心、留着外功防御"。

## 比较边界与测试纪律
- **毕业率/基准只在「同流派+同分支+同方案」内比较**，跨分支/跨流派无意义。
- build 包验收只有四条：事件完整、技能倍率与同源 Excel 一致、引擎跑通、同分支内能生成毕业基准。
- **方案配错不放进 UI**：校验前置到 `tools/check_templates.js`（`npm run check:data`，已在 `npm test` 链首）。
- **四栏骨架（2026-10-30 定稿勿回退）**：`.studio` = `minmax(0, max(33.33vw,400px)) minmax(0,.9fr) minmax(0,.92fr) minmax(0,.95fr)`，**无 justify-content:center**（两侧大留白的元凶）；body 两侧 padding 12px（= 卡片间距，studio.css 覆盖 style.css）；栏1 的 `.st-kj-row`/`.st-slots` 保 `width:660px; max-width:100%`（栏窄随缩、超宽居中且上下对齐）；≤1150 单列。
- 全量 `npm run test:all`（UI 冒烟 = `tools/test_studio.js`，现 **260 项**）。golden 是防回归底线，偏差必须查根因，**不许改基准洗绿**。方案文件增删/改名后重跑 `npm run build:index`。
- ⚠ `cssBlock()` 用 `indexOf('}')` 截规则 ⇒ **CSS 注释里不能出现 `{}`**，否则断言取到的规则被截断。

## 外部数据源
- **燕小叽 yysls-assistant.cn**（作者 = Excel 计算器作者）：`tools/extract_from_site.mjs <轴名> <输出前缀>`。唯一实质差异 = 属性固伤×1.5（项目有、站点无）。详见 `燕小叽站点研究与纯唐轴提取.md`。
- **yysls.destiny.cool** 解包字典 `/equip/decoded/<name>.json`；`xinfa.json` 60 条全覆盖，已落 `web/assets/img/mind-official/`。名称差异：星火燎原=官方「燎原星火」、归雁经=官方「归燕经」。详见 `destiny站点研究与官方素材获取.md`。
- **心法图标 = 官方白描图**：官方**图与卡底分离**，`mindTileHtml(key,size,{card})` 运行时组合 = 卡底 + 白描图标 + **流派横幅** + **文字心法名**。卡底 png 自带 alpha（顶部尖角透明），**不能加 background-color 打底**，提亮走 `::before` + `filter:brightness()`。品质三档：金 13 / 蓝 6 / 紫 41，每流派 1 金 + 3 紫。
- **流派横幅 = `xinfa/liupai_pic_big_url/` 的 254×68 条幅**，落 `mind-tag/<大写ID>.png`（含 `TONGYONG.png`）。破竹·樽官方漏填 → 用户游戏内截图 + `tools/make_mind_tag.mjs` 贴官方无字底合成，12 流派已齐。心法→流派由官方 `xinfa-map.json` 的 `type_name` 给。
- **流派印章** `kongfu/liupai_pic_url/`（11 张，文件名哈希）。识别法 = 印章上的字即**流派名第二字**。已裁透明留白。
- **⚠ 卡片内图片必须夹宽度**：`.st-mind-card` 用 `grid-template-columns: minmax(0,1fr)`；img 自动最小尺寸是原生像素宽（横幅 254px），不夹会顶宽网格列。
- **截图归一化管线**：`tools/pnglite.mjs`（零依赖 PNG 读写 + Lanczos）+ `tools/make_mind_tag.mjs`。按墨块 bbox 裁剪 → alpha **预乘**后 Lanczos（不预乘会渗黑边）→ 微锐化 → 反预乘。

## 实测规律
- **会心率最优条数 = 把面板顶到 80% 所需的最少条数**，多一条完全浪费。边际：会心率单条 +2.8~3.4%；属性攻击单条 +0.8%（承音 74.5）。
- **无相攻击加算到主属性上**，与四属性同区间 → 「最大裂石5+最大无相2」= 7 条属性攻击。
