# 2026-11-02 · 助手「周黑线」骨架

## 做了什么

新增 AI 助手（占位人格「周黑线」，用户自定的临时名），把工作台从两栏改回三栏可切换结构。整条链路跑通，**人格与立绘是占位**。

- 布局：`.studio.assist-on` + `--assist-w` 一个变量切三栏；≥1600 默认展开，1200~1600 两栏 + 右下角圆形入口，<1200 她全屏 + 底部三视图图标栏（`#st-dock`）。默认仍是两栏，旧断言不破。
- 新文件 `engine/assist.js`（纯函数）：意图规则 `intentOf`、部位/武器类型识别、中文 bigram 分词、md 解析与检索 `searchKb`、事实快照 `compactFacts`。
- 新文件 `web/assist.js`：消息流、卡片消息（背包/配额/录入/装备）、chips、主动提示去重、接入设置、SSE 流式。**不 import studio**，靠 `assistHost` 依赖注入。
- 知识库 `data/kb/`：index.json + 三篇机制文档（品相 / 转律 / 配额），front-matter 作索引。
- 测试 `tools/test_assist.js` 48 项，已并入 `test:all`。

## 关键决定（都是和玩家讨论后定的）

1. **她是入口不是附件**，但每个能力都留按钮路径 —— 模型挂了工具不能废。
2. **对话历史可以直接丢，不做摘要、不做"新对话"**。这个工作台的事实活在引擎里，不在对话里，所以截断照样答得对。ChatGPT 类应用必须摘要，是因为它们的世界知识全在上下文里。
3. **提示去重按「件 × 结论」不按时间窗**。我最初提的 24h 窗口被玩家否掉：连录五件只提示一次会漏掉后面更好的。结论变了要重说。
4. **顺带留个操作日志**：聊天流天然就是操作日志和撤销栈，不用另做历史面板。
5. 主动开口只有三种：录进来的件值得动 / 背包凑出更优组合 / 可转律补齐缺口（第三种未接）。

## 踩坑

- `.st-assist-panel` 只写 `max-height` 不写 `height`，`flex:1` 的消息区会缩到内容高度，整块塌成一条。必须给死高度。
- headless 截图用 `--window-size` 会带 DPR 偏差，改成 CDP `Emulation.setDeviceMetricsOverride` 才准。写了 `.tmp/probe.mjs` 做一次性探针（能跑表达式 + 截图），查交互很方便。
- `disposeHtml` 里那段 `disposeItem` 调用抽成了 `disposeResultOf(piece)`，详情页与主动提示共用一份判断 —— 两处各算一遍迟早分叉。

## 修：切换方案时助手误报「能换 X 件」，点开却是"已最优"（同日）

玩家实测：切方案后周黑线说"现在能换 N 件"，列的件都不对；点「看怎么换」模态框却说"当前组合已是最优"。

**根因**：`actions.pickConfig` 是两段式 —— `await switchBranch(branch)` 内部 render 一次，`switchPlan(plan)` 再 render 一次。
第一次 render 时分支已换、方案还是该分支的默认方案，而且 `switchBranch` 里 `rebuildGear()` 刚把 equipped 重建为**空**（新分支的 loadout 没配过）。
这时 `searchBestComposition` 面对 8 个空位，会把背包里随便什么件都当成"能填"，于是 `status='improved'`；
`maybeNotifyComposition` 在 render 末尾就地开口，把过渡态当成了结论。第二次 render 才是真实态（配满 → optimal）。

**修法**（两层，缺一不可）：
1. `state.switching` 开关：`pickConfig` 期间置 true，`maybeNotifyComposition()` 直接 return（**不记 compBase**，否则会把过渡态签名当成基线），`finally` 里清标志再统一判一次。
2. 600ms 防抖 + 复核：定时器回调里重新读 `state.search.result`，`compositionSig` 与发出时不一致 → 作废。覆盖"切换之外的异步二段变化"（如 build 包加载后二次 render）。

教训：**主动提示不能在 render 里就地发**。render 是"当前帧"，不是"稳定态"；凡是会连跑多次 render 的操作，都必须等它跑完。

测试 test_assist 51 项（新增"防抖复核"断言），test_studio 68 项，全绿。

## 九改：MiniMax M3 思考链不折叠 + 轮次上限（同日，玩家实测反馈）

玩家用 MiniMax 官网 M3 测：思维过程一直在正文里涌出来，想完之后又看不见；只留下工具记录。另外"思考半天结论"换来一句兜底话术。

**根因 1（思考链）**：MiniMax 默认把思考**塞在 `content` 里**，不主动分离。文档里 `reasoning_split: true` 才会把思考放到 `reasoning_content`；而且它另一个接口的字段名叫 `thinking_content`（移动云文档示例）。我原来只认 `reasoning_content` / `reasoning`，一个都没命中 → 思考当正文流出来。而 `runTurn` 最后用最后一轮 `content` 覆盖 `node.text`，前面几轮混进去的思考就被抹掉了 —— 所以"想完就看不见"。

修：
- 请求体对 MiniMax 加 `reasoning_split: true`；判定同时看 baseUrl **和模型名**（中转站代理时 baseUrl 看不出是谁）。
- 思考字段三个都认：`reasoning_content ?? thinking_content ?? reasoning`。
- 思考走 `onReason` → `node.think`（折叠块），不再进 `.st-txt`；`node.text = answer` 也不会覆盖它。

**根因 2（截断）**：不是 max_tokens，是我写的 `runTurn` 只循环 **4 轮**。思考模型一轮只查一块数据，很快撞上限，然后返回兜底句。

修：
- `MAX_ROUNDS` 4 → 6；第 `MAX_ROUNDS-2` 轮起注入 system：「不要再调用工具，直接用已有信息回答，缺哪块就直说」。
- 顺手给 MiniMax 显式 `max_completion_tokens: 32768`（不传可能被默认值卡住，表现同样是"想了很久什么都没说"）。
- 识别 `finish_reason === 'length'`：有内容就补一句"后面被截断"，没内容就说"想得太远被掐断，你问具体点"。
- 兜底文案从"这件事我想绕远了"改成说明下一步该怎么问。

测试 assist 62 项，全绿。

## 十八改：规则 1 补档位门槛（同日，玩家实测抓到的真 bug）

现象：身上穿**天阶**，背包这件**玄阶**，转律后只能到**地阶**，引擎仍旧说"转律之后穿上吧"。

**根因**：`disposeItem` 的规则 1（转律后穿上）只看两件事 —— `Δ转后 > Δ现状 + 死区` 和 `全局必需`（必修 / relief 非空），
**完全没有看转后档位**。规则 1 又排在规则 2/3（比档位）之前，所以"能补一条配额"就能压过"要降两档"。

**修**：加 `转后不降档 = rankOf(转后档) >= rankOf(oldTier)`，串进规则 1 的判定。
- 用 `>=` 不是 `>`：**转后同档允许**（同档之争，配额说话）。
- 拦住之后自然落到规则 4（`bestTier = max(转后档, 当前档)` ∈ {天,地}）→ 放背包。✓
- 同批把规则 4 的「X 阶难得」从 `gNow.tier` 改成 `bestTier` —— 这件现在玄、转后地，说"玄阶难得"低估了它。

**为什么会出现这种数据**：`gradeItem` 的 k/m 按**本部位排列**算，`quotaCensus` 的缺口按**全队配额行**算，两套口径不同源 ——
本部位天阶（5 条全对）但全队某行仍缺，换成本件、转律补上那行，就会出现"降本部位档、补全局缺口"。
玩家的裁决很明确：**档位优先，降档不换**。

**复现不了**：破竹风这套里转律总能回到天阶，构造不出"转后 < 已穿"的用例。
所以测试用源码断言锁住门槛（`1.6`），并在 `评价系统设计.md` §11.3 规则链里写成条文。

测试：dispose 57、studio 73、assist 65，全绿。

## 二十改：移动端选项卡点不动 / 输入框消失 + 改名（同日，玩家实测）

**现象**：手机上无法切选项卡，且助手视图没有输入框。

**根因 1（切不动）**：移动端 `#st-assist` 的显示同时受 `.studio.assist-on` 和 `body[data-mview]` 两条规则管。
`.studio.assist-on #st-assist{display:flex}` 特异性 (1,2,0) 高于 `body[data-mview="gear"] #st-leftcol` (1,1,1) ——
**只要 assist-on 还开着**（桌面端宽屏时默认展开、localStorage 又记住），切到装备/面板时全屏助手面板依旧盖在上面，
看起来就是"点不动"。修：移动端媒体查询里三条 `data-mview` 规则加 `!important`，视图只由 data-mview 决定。

**根因 2（没输入框）**：`#st-assist .st-assist-panel { position: fixed; inset: 0 }` 铺到视口底，
而 `#st-dock` 是 z-45 的固定条（52px）—— 输入框正好在面板最底部，被整条盖住。
修：`inset: 0 0 52px 0`，让出切换栏高度。

**顺带**：
- 移动端隐藏「收起」（`.st-assist-collapse`）—— 三视图靠底栏切，这按钮点了没反应。
- 底栏文案：助手 → **红线**，读数 → **面板**，装备不变。`data-mview-btn` 的键（assist/gear/read）**不改**，
  assist.js 靠它定位。

实测 430×860：assist-on 开着时 gear/read 都能切（left/right flex、assist none）；
面板底边 808 = 860-52，输入框可见；底栏「红线 / 装备 / 面板」。桌面 1700 不受影响（面板仍是 relative、收起可见）。

测试：assist 68（新增 3 条：data-mview 独占、52px 留白、底栏文案），studio 80、dispose 57，全绿。

## 二十一改：移动端锁视口，滚动收进内容区（同日，玩家实测）

玩家：手机上还要往下滑一点才能看见底部选项卡 —— 标签应该常驻底部，内容多就让它在上方区域滚。

**根因**：`.studio` 高度随内容长（移动端 `display:block`、栏高 100% 但父高不定），整个页面能滚。
底栏虽然 `position:fixed; bottom:0`，但页面一滚，可视区坐标变，标签就"掉"到屏幕外，得滑回去。
另外移动浏览器 `100vh` 含地址栏高度，底栏会被压出屏幕。

**改**：
- `html { height:100%; overflow:hidden }`；`body { height:100vh; height:100dvh; padding:0 0 52px }`（dvh 兜 vh）。
- `.studio { display:block; flex:1 1 auto; min-height:0; overflow-y:auto; -webkit-overflow-scrolling:touch; overscroll-behavior:contain }` —— 页面不滚，滚动在内容区。
- `.studio > .st-col { height:auto; min-height:100%; overflow:visible }`（原来 height:100% 会让栏内卡片互相挤压而不是溢出）。
- `#st-leftcol, #st-right { overflow:visible }`（桌面是 hidden，移动端会把内容裁掉、外层的滚动也滚不到）。

实测 430×860、背包 30 件：`.studio` 660/769 自滚，页面 `scrollHeight == innerHeight` 不滚，
滚到底后底栏仍在 808~860；assist 面板 0~808、输入框 762~808；
read 视图右栏 774 高，同样在 `.studio` 里滚。桌面 1920 完全不受影响。

测试 assist 69（新增一条），studio 80、dispose 57，全绿。
