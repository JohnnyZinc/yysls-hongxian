# 2026-10-27

## 武器槽模型重构：删除「左右武器 + 排列枚举」

起因：用户指出「剑增只可能出现在剑上，鸣金虹必带一剑一枪，剑就必须有剑增」，质疑引擎为何把剑增判成非必备。

排查结果（用户完全正确，引擎错了）：
- 排列内部判定是对的（左武器=剑时必备含 `[剑增/枪增]×1`）；
- 坏在两处：① `quota.js` 合并时跨排列取 `Math.min`，把约束抹成 0；② `advisor.js` 评分时无类型信息，「无剑增的剑」被匹配到枪槽 → 判天档。
- 根因：当初为表达「不分左右」用「左/右槽 + 互换排列」绕弯，反而绕错。

改动：
- `engine/quota.js`：`SLOT_DEFS` 改 `武器1/武器2`；`loadSlotModel` 按绑定类型裁剪调律池（剑槽只含剑增）；删除排列枚举与 `any_of` 组探测；合并保留 `outOfPool`；输出 `weaponTypes`/`slotTypes`。
- `engine/advisor.js`：新增按 `item.weaponType` 只匹配本类型槽（剑只匹配剑槽）。
- `toGradeItem()`（studio/inspect/swap）补传 `weaponType`；graduate 用 `slotTypes[slot]` 声明。
- `web/studio.js`：存储键 `左武器/右武器 → 武器1/武器2` + 读档迁移；去掉用户可见文案里的「左右」。
- `panel.js` / `graduate.js` / `swap.js` 同步槽位名。

验证：全量测试绿（方案校验 35/35、golden 12/12、dps 11/11、panel 44/44、quota 45/45、advisor 47/47、monitor 42/42、swap 21/21、inspect 16/16、graduate 21/21、studio 180/180）；22 个方案的指定增归属 100% 正确。
