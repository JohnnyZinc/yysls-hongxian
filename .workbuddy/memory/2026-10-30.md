## 修两个跨方案区块的 bug（用户报）

**1. 方案标签显示拼音分支名（feitianyu / chuntang…）**
- 分支中文名的唯一来源 = `data/template/<流派>/_meta.json` 的 `分支.<id>.name`。
- `flowLabel(meta, schoolName, branch, plan)` 改为先查 `meta.分支?.[branch]?.name`，查不到才回退 id；方案名用 `PLAN_CN`（dawai→大外流 / xiaowai→小外流）。
- 标签格式 `流派·分支·方案`，无分支则 `流派·方案`。已验证 22 个方案全中文：牵丝玉·飞天玉·大外流、裂石钧·纯唐轴·小外流、牵丝霖·火拳奶·大外流 …

**2. 已穿戴**武器**点开「其他方案的适配」永远停在"展开后加载…"（背包件正常）**
- 根因：`crossFlowHtml(piece, 'equipped', piece.slot)` 传的是**部位值**「武器」，但 `state.equipped` 的键是**存储键**「武器1/武器2」⇒ `state.equipped['武器']` 取不到 ⇒ `if (piece) fillCrossFlow(...)` 不执行 ⇒ 永久停在占位文案。
- 背包件用 uid 定位所以不受影响；防具部位值=存储键所以也不受影响 —— 只有武器会中招。
- 修复：`equippedDetailHtml(piece, slotKey)` 增加存储键参数，renderModal 传 `s.slot`；`crossFlowHtml` 用 slotKey。
- 另加兜底：取不到本件时明确显示"未找到该装备（kind/ref）"，不再静默卡住。
- 新增断言防回归：`data-ref="武器1"` 且不含 `data-ref="武器"`。

## 教训
- **部位值 vs 存储键必须分清**：武器部位值恒为「武器」，存储键是 武器1/武器2。凡是回查 `state.equipped` 的地方都必须用存储键。
- 异步填充的折叠区要有失败兜底文案，否则出错时表现为"卡死"，很难定位。

测试：`test_studio` 185/185，全量绿。

## 口径卡改版：恒一行 + 高度对齐（用户定稿）

**需求**：流派改成「图标左 / 名称右」；图标与名称等高（约心法图标一半）；流派条顶部与心法图标顶部对齐；
分支/方案放到流派条下方，三者（流派+分支+方案）整体高度 = 心法图标高度，且宽窄屏都必须同一行；
去掉「口径（半固定层）」标题与「心法 点击槽位更换 · 悬停看属性」文案。

**做法**
- HTML：`.st-kj-row` > `.st-kj-left`（流派条 + `.st-kj-flows`）+ `.st-kj-right`（`.st-minds`）；
  标题行删掉，只留 `.st-kj-head` 里的「恢复方案默认」。
- `.st-kj-row`：`display:flex; align-items:stretch; flex-wrap:nowrap`（原 5 列栅格与 ≤1000px 换行断点全删）。
- 高度一致**不写死像素**：stretch + 左栈 `space-between` 自动撑满心法图标高度；
  流派条 `flex:1 1 auto; max-height:96px` 吸收余高，无分支流派（单个方案下拉）也不会留大空洞。
- 流派条：图标 56×56（`object-fit:contain`，立绘竖版，cover 会切掉纹样顶部），名称 40px / `line-height:56px`（= 图标高，字形垂直居中）。
- 分支/方案：`label` 与 `select` **同一行**（省掉 label 独占的一行 ≈13px/个），箭头改 `top:50%` 居中。
- 心法图标尺寸改走 CSS 变量 `--mind-w`（`mindTileHtml` 不再写内联 px），`@container 600/470px` 两档同比缩。

**踩坑**
1. 基类 `.st-field label { width:70px }` 会把下拉挤到 42px 宽（"大外流"被截）→ 口径卡里必须显式 `width:auto`。
2. 基类 `.st-field` 有 `align-items:center`，竖排时 label 会缩成内容宽并**居中**（看着像没左对齐）→ 用 `flex-direction:row` 绕开。
3. 一开始图标用 `cover`（42px）时流派条只有 66px，两个下拉放不下（>143px 心法高）→ 图标放大到 56 但下拉改横排才塞得下。
4. 编辑本仓库时，python heredoc 里的 `\s` / `\"` 被环境吃成 `/s` / `/"`，写进 JS 会直接语法错误
   → 改测试断言时**避免反斜杠**（用 `.includes()` + `indexOf` 切片替代正则），必要时用 Write 工具落一个 .py 再执行。

**测试**：`test_studio` 225/225（新增/改写：口径卡无标题无说明文案、左栈结构、图标在名称前、
flex+nowrap 恒一行、图标高=名称 line-height、stretch+space-between），全量 `npm run test:all` 绿。
