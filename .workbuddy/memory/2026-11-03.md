### 抠图（`tools/cutout.py`，新文件）
- 环境：本机 pip 默认走清华源，装等不到包；`--index-url https://pypi.org/simple/` 才通。装了 pillow / numpy / scipy。
- 算法要点：
  1. 背景色取**边框环中位数**（图有轻微渐变，取角点会偏）。
  2. 判背景 = `色差<14` **且** `与边框连通`。只按颜色一刀切会把白色衣袖一起吃掉（袖子色差仅约 19，靠连通性保住）。
  3. 收缩 1px + 高斯羽化 → 去白边；边缘像素做 unpremultiply，把混进去的浅灰白反解掉，深色面板上不会发光。
  4. **脚下一圈被围住的背景**（鞋子+裙摆+投影围成的口袋）与边框不连通，flood fill 抠不到 → 在下方 14% 里从「确定是背景」的内芯再长一次，长到色差 34 停手。不处理会在鞋边留一块浅灰。
  5. 归一化：按人物高度 1180 统一缩放（玩家说四张身高略有差异）、脚底对齐、**头部中线**（顶部 22% 的 alpha 质心）居中。
  6. 横向裁到人物包围盒（左右 10px）—— 留大片透明会让前端算出的比例失真，人物看起来永远很小。
- 输出：`web/assets/img/char/hongxian-<情绪>.webp`（90KB/张）+ `manifest.json`；png 母本进 `素材库/周红线/_抠图/`（web 目录不放大文件）。
- 实测四张并排：白边干净、身高/脚底对齐、无空洞。

## 立绘取景第二次修正（同日，玩家实测）

**桌面**：立绘在原窗口里"特别高，头顶顶到设置/收起"。根因是我按**栏宽** 38% 定尺寸 —— 图是 410:1300 的竖条，
宽度一定高度就是 3.17 倍，1920 下占面板 94%。改成按**高度**定：`--pt-h: 66%`（对话框 2/3），宽度自然推出。
文字避让宽度也必须跟着高度算，写成 `calc(66cqh * 0.315 + 22px)`；面板加 `container-type: size` 才有 `cqh`。
（用 `%` 是相对宽度，宽屏上会避让过头。）

**移动端**：玩家要的是「立绘整屏高 + 对话从腰线往下堆 + 腰线以上一个字都没有」。上一版我做成"人物站下半场、消息从顶上流"，理解错了。
- 立绘 `height:100%`；`::after` 从 28% 开始压深、48% 到 .82、62% 近乎实心。
- flow 改 `flex:0 1 auto; margin-top:auto; max-height:46%; justify-content:flex-end` —— 贴底堆，46% 封顶（≈ 腰线），超了内滚。
- **名字 + 设置/收起那行必须挪到底部**（`order` 重排：flow 1 / head 2 / set 3 / chips 4 / input 5），否则它会压在她头顶上。
- 46% 是试出来的：52% 时文字落在胸口、压在浅色衣服上读不清；46% 正好压到裙摆（深色 + 墨纱）。

测试 assist 80 项（三条断言跟着改：--pt-h、cqh 避让、移动端满高 + 46% 封顶 + head order）。
